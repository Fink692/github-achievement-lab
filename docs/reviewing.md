# Lightweight review guide

Review the behavior and the communication around a change.

## Review order

1. Check that the change addresses the linked issue.
2. Look for correctness, edge cases, and unintended behavior.
3. Check that tests or verification notes support the claim.
4. Check whether the documentation remains accurate.

Give actionable feedback with a reason and, when useful, a concrete alternative. Mark non-blocking ideas as suggestions so the author can distinguish them from required fixes.
