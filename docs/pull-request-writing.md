# Pull request expectations

A pull request should make the change easy to understand and verify.

## Before opening

- Confirm the branch contains only the intended change.
- Re-read the linked issue and make sure the scope still matches.
- Run the smallest relevant check.

## In the description

- Explain what changed and why.
- Link the issue with Closes #<number> when the change completes it.
- State what you verified and call out anything not tested.

Prefer one coherent change per pull request over a collection of unrelated edits.
