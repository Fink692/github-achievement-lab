# Writing effective issues

A good issue gives the next contributor enough context to make progress without guessing.

## Include

- **Context:** what prompted the issue?
- **Outcome:** what should be different when it is complete?
- **Constraints:** what should remain unchanged?
- **Acceptance criteria:** how will we know the work is done?
- **References:** link related files, issues, or examples.

Use a specific title and separate the problem from proposed implementation details when possible.
